# Phase 0 review methodology lessons

Use this when preparing or reviewing capability-reuse Phase 0 evidence. The implementation can be strong while empirical closure is still invalid if the evaluation is circular, synthetic, or simulated.

## Official status discipline

Do not claim `PHASE_0_EMPIRICAL_CLOSURE_PASS` unless C1-C10 are backed by independent evidence. The acceptable interim status after the 2026-07-27 review is:

```text
PHASE_0_TOOLING_AND_CORPUS_COLLECTION_COMPLETE
EMPIRICAL_LABELING_AND_INDEPENDENT_VALIDATION_PENDING
```

Passive live shadow may continue. Formal Phase 1B remains not authorized. Active engineering smoke must stay limited to `hmp-healthcheck@1.0.0`; `hmp-send` remains mutating/unsafe/not active.

## Reviewer-rejected evidence patterns

Avoid these when assembling closure evidence:

1. Synthetic holdout as the whole holdout.
   - Examples like `... variant 1`, `... variant 6` are development fixtures, not independent holdout.
   - The same base templates must not appear on both tuning and holdout sides.

2. Labels generated by the same rules being evaluated.
   - If regex buckets assign the operation and those buckets also assign the label, Dataset B is circular.
   - Human or independently reviewed labels must be blind to generated operation buckets and predictions.

3. Precision measured by a proxy classifier.
   - C6 must evaluate the actual retriever pipeline: candidate scores, hard filters, margin, compatibility, trust/effect/allowlist eligibility, and final intervention decision.
   - A second keyword classifier that mirrors the expected labels is invalid even if it reports 100%.

4. Safety demonstrated only by predictor-owned hard negatives.
   - C7 requires independently authored/read human-reviewed mutating hard negatives and evidence that read-only capabilities do not match mutating requests.

5. Simulated conformance represented as runtime conformance.
   - Local callback/harness tests are implementation evidence.
   - C8 needs raw evidence from the pinned CLI/gateway dispatcher path. Delegation may be explicitly unsupported/unknown, but must not be simulated as pass.

6. Thresholds selected from smoke behavior.
   - C10 requires threshold/margin sweep with precision, recall, false effect matches, intervention count, and preferably confidence bounds.

7. Misleading coverage math.
   - Do not calculate top-10 coverage by summing all buckets when there are fewer than ten buckets.
   - Report recognized recurring categories with minimum occurrence thresholds separately from `unknown_other` and one-offs.

## Required next evidence shape

- Dataset B: 100-150 post-execution pairs, manually or independently labeled as `same_reusable_operation`, `related_but_different`, `unrelated`, `incompatible`, or `uncertain`.
- Dataset C: at least 100 real or independently authored hook-visible requests, with no template leakage between tuning and holdout.
- Retriever evaluation: real retriever calls and full candidate/eligibility trace, not regex proxy predictions.
- Threshold sweep: threshold and margin grid over tuning and frozen holdout.
- Runtime conformance: raw pinned CLI/gateway dispatcher artifacts; unsupported surfaces labeled unsupported/unknown rather than passed.
- Recurrence validation: manual cluster review excluding debugging/retry loops and proving recurrence across sessions or days.
