# v2.3.0 entrypoint release correction — 2026-07-29

## Reviewer finding

A reviewed v2.3.0 archive had a release-assembly regression in top-level `plugin/__init__.py`:

- it called `retriever.retrieve()` directly without `shadow_mode=False`, so active retrieval never created interventions;
- `pre_tool_call` returned `None` for every `execute_code`, bypassing `ctrl.authorize_execute_code()`;
- post-tool outcome classification treated non-empty error/block strings as success;
- execute-code start/completion events lost correlation identifiers;
- the archive contained a nested stale full skill at `capability-reuse/capability-reuse/`.

## Correction applied locally

- Restored the controller-based entrypoint logic into top-level `plugin/__init__.py`.
- Kept dynamic `_mode()` rather than module-level `MODE`.
- `on_pre_llm_call()` now routes through `ctrl.retrieve()`, persists decisions, and renders injection only when active retrieval returns a decision.
- `on_pre_tool_call()` now routes `execute_code` through `ctrl.authorize_execute_code()` and returns Hermes block contracts for denied calls.
- `on_post_tool_call()` now routes through `ctrl.record_tool_outcome()`.
- Removed nested duplicate `capability-reuse/` skill directory.
- Aligned `plugin/protocol.py::VERSION` to `2.3.0`.
- Synced corrected `plugin/` source to runtime `/root/.hermes/plugins/capability-reuse/` before validation.
- Regenerated `evidence/deployment-manifest.json` and `evidence/SHA256SUMS`.
- Packaged corrected local archive: `/tmp/capability-reuse-v2.3.0-corrected.zip`; final archive SHA256 is recorded externally in `/tmp/capability-reuse-v2.3.0-corrected.zip.sha256` because embedding the archive hash inside the archived manifest/reference would be self-referential.

## Regression coverage added

`tests/test_phase1b_active_healthcheck.py::test_plugin_entrypoint_routes_through_controller_active_blocking_and_correlation` verifies:

- shadow mode does not register `invoke_capability`;
- active mode registers `invoke_capability` after env change in same process;
- active `on_pre_llm_call()` injects an `hmp-healthcheck@1.0.0` intervention;
- active `on_pre_tool_call("execute_code", ...)` blocks raw fallback;
- start/completion events preserve `session_id`, `episode_id`, `turn_id`, `tool_call_id`, and `retrieval_event_id`;
- blocked completion logs `outcome=blocked` and `block_origin=protocol`.
