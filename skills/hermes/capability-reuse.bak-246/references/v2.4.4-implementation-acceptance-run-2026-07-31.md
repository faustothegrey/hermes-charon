## Pitfalls discovered and fixed during run

1. **False PASS with zero events**
   - Initial peer70 run produced `total_fresh=0` but `VERDICT: PASS`.
   - This is invalid. Acceptance must fail when `total_fresh < 20` or `total_fresh > 30`.

2. **Nested event payloads**
   - `event_store.emit()` writes metadata inside `event.data`, not at top-level.
   - Acceptance/analyzer code must inspect `event.data` for `deployment_id`, `cohort_label`, `plugin_version`, provenance, peer_id, traffic_type, and chain fields.

3. **Contaminated clean cohort from earlier bad acceptance attempts**
   - Earlier flawed acceptance scripts wrote partial/bad v2.4.4 clean events.
   - Final analyzer must filter to the **current immutable deployment_id**, not just `cohort_label == v2.4.4_clean_live`.

4. **Analyzer must validate clean cohort, not backlog**
   - `batch-reuse-analyzer.py` must separate `legacy_or_pre_events` from the current deployment and report chain errors only for the current clean cohort.
