## Semantics implemented

- Skill/plugin version bumped to `2.4.5` on peer70.
- Retrieval event schema bumped to `1.2` for new events.
- Review record schema: `1.0`.
- Preview schema: `1.0`.
- Requester block keeps actor and transport orthogonal:
  - `actor_type`: `human | agent | scheduler | service | unknown`
  - `request_channel`: `telegram | hmp | cron | local | api | gateway | unknown`
- Reviewer fields keep identities separate:
  - `requester_peer_id`
  - `processing_peer_id`
  - `target_peer_id`
- Shadow retrievals use `candidate_capability`, not `selected_capability`.
- Raw request text is not exported; review records use:
  - `redacted_text`
  - `raw_request_ref`
  - `redaction_status`
- Canonical execution preview and dispatch share `execution_plan.build_execution_plan()`.
- `hmp-healthcheck@1.0.0` preview is deterministic, network-free, exact-version-aware, peer-map based, and secret-free.
- Unsupported targets get `preview_status=unsupported`, `executor_kind=unresolved`, and a `NOT EXECUTABLE` preview.
- Auth fields use:
  - `auth_mode`
  - `credentials_exposed_in_preview`
- Stable `review_id` is derived from retrieval event + capability + version + rank.
- Human labels are append-only in `review/human-labels.jsonl`; generated queues join latest label.
- CSV exports neutralize formula injection.
- Synthetic/acceptance rows and organic review rows are exported separately.
