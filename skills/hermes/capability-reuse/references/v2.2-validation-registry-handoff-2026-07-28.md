## Local validation checklist

Run from the skill directory:

```bash
cd ~/.hermes/skills/hermes/capability-reuse
python3 -m compileall -q plugin scripts instrumentation tests
python3 -m unittest discover -s tests -v
python3 scripts/conformance-suite.py --profile full-required
```

Also verify source plugin and runtime plugin are byte-for-byte synced before measuring or shipping:

```bash
python3 - <<'PY'
import filecmp, os, sys
src=os.path.expanduser('~/.hermes/skills/hermes/capability-reuse/plugin')
dst=os.path.expanduser('~/.hermes/plugins/capability-reuse')
files=['__init__.py','compatibility.py','dispatcher.py','event_store.py','plugin.yaml','protocol.py','registry.py','retriever.py']
missing=[]; diff=[]
for f in files:
    sp=os.path.join(src,f); dp=os.path.join(dst,f)
    if not os.path.exists(dp): missing.append(f)
    elif not filecmp.cmp(sp,dp,shallow=False): diff.append(f)
print({'missing':missing,'diff':diff,'runtime_sync_ok':not missing and not diff})
sys.exit(0 if not missing and not diff else 1)
PY
```

## Packaging and versioning pitfalls

When peer70 is expected to generate the next release number, still ensure the artifact and its metadata agree before final upload. In the v2.2 handoff, the first package shipped with SKILL.md still at 2.1.0 while peer70 generated 2.2.0, leaving plugin metadata stale. Fix was to bump both:
- `SKILL.md` frontmatter `version: 2.2.0`
- `plugin/plugin.yaml` `version: 2.2.0`

Then rerun compile/tests/conformance and rebuild the zip.

Packaging pattern:

```bash
cd /tmp
( cd ~/.hermes/skills/hermes && zip -qr /tmp/capability-reuse-vX.Y.Z-validated.zip capability-reuse -x '*/__pycache__/*' '*.pyc' )
sha256sum /tmp/capability-reuse-vX.Y.Z-validated.zip > /tmp/capability-reuse-vX.Y.Z-validated.zip.sha256
unzip -t /tmp/capability-reuse-vX.Y.Z-validated.zip
```

## Deploy pitfalls

HMP self-deploy messages that restart the gateway may leave the original HMP message stuck in `working` because the restart interrupts response completion. Do a separate status-only HMP message after restart to verify versions and health instead of assuming failure.

For peer128 v2.2, deploy partially completed with plugin v2.2 but SKILL.md remained v2.1.0. A follow-up “FIX SKILL only” HMP message downloaded the same zip, replaced only the skill directory, and confirmed:
- SKILL.md v2.2.0
- plugin.yaml v2.2.0

For peer84, respect cooling/offline windows. If it is down/refused during deployment, schedule a one-shot `no_agent` retry after the cooling window rather than blocking the current session. The retry script should run from `~/.hermes/scripts/`, use peer70 as the bridge if direct SSH from peer106 is not appropriate, copy the v2.2 zip, update skill+plugin, clear `__pycache__`/`*.pyc`, restart gateway, verify health, and update peer70 registry manifest.
