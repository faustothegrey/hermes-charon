Unit/integration pass for the telemetry/correlation spec (peer70), split with
peer141 (e2e 7/10-12). Suite went 72 → 92/92 unittest (+3/3 standalone

## Bugs fixed (code, not tests)

### 1. HMP adapter emitted fake retrieval events (spec 5/6 violation)
`~/.hermes/plugins/hmp/adapter.py` consumer_loop called
`emit_retrieval(candidates=[], top_score=0.0, ...)` for EVERY HMP message,
including REGISTRY_PUBLISH. With the old `whole_request_covered=True` default
this reproduced the exact v2.4.16 "impossible combo" the spec bans:
`candidate_count=0, top_score=0, whole_request_covered=true`. Also classified
ALL HMP traffic as `organic_peer` (registry_sync invisible to recurrence).
Fix:
- `emit_retrieval` default `whole_request_covered: bool = True` → `bool | None = None`.
- Adapter passes `retriever_executed=False`, `whole_request_covered=None` and
  explicit non-evaluated stages
  (`{"retrieval": {"executed": False, "candidate_count": 0},
     "coverage": {"evaluated": False, "whole_request_covered": None},
     "eligibility": {"evaluated": False, "eligible": None}}`).
- `traffic = "registry_sync" if text.startswith("REGISTRY_PUBLISH") or
  "registry sync" in text.lower() else ("organic_peer" if requester_peer else
  "unknown")` applied to the retrieval + both surface_execution events.
- Note: the hmp plugin is RUNTIME-ONLY (`~/.hermes/plugins/hmp/`, v0.1.4) —
  no skill-source copy to sync. The capability-reuse plugin (event_store/
  retriever) DOES have skill-source copies that must stay hash-identical.

### 2. cohort.json is the event-metadata source of truth
`v244_metadata.cohort_fields()` reads `~/.hermes/data/reuse-observer/cohort.json`
and `mandatory()` stamps `deployment_id / deployment_timestamp / plugin_version /
plugin_artifact_hash / schema_version / cohort_label` on EVERY event from it —
NOT from the `PLUGIN_VERSION` constant. The file was stale (v2.4.6, schema 1.2,
placeholder hash `v245-reviewer-queue-local`), so even with
`PLUGIN_VERSION="2.4.18"` in code, every new event would carry the wrong
cohort → release gate "zero v2.4.18 events with v2.4.5/v2.4.6 cohort or
placeholder artifact hash" fails at runtime despite green tests.
Fix (per release):
1. `cp cohort.json cohort.json.bak-<ver>` first.
2. Compute artifact hash exactly like conformance-suite.py:
   `h = sha256(); [h.update(f.read_bytes()) for f in sorted(Path(plugin).rglob("*.py"))]`.
3. Write `dep-v<ver>-<8hex uuid>`, `plugin_version=<ver>`, real hash,
   `schema_version=<new>`, `cohort_label=v<ver>_live`.
Live example: `dep-v2418-48d39428` / `c861593e...` / 1.3 / `v2.4.18_live`.

### 3. Traffic taxonomy incomplete (spec 8)
`_extract_traffic_type` only knew organic_user/organic_peer/cron/
acceptance_test/unknown. Extended to the full 10-category set:
`organic_user, organic_peer, scheduled_protocol, registry_sync, cron, retry,
test, acceptance, calibration, unknown`. Signature gained `user_message=""`
(param passed from `retrieve()`). Mapping: explicit ctx flag passthrough;
`is_calibration`/msg startswith "calibration" → calibration; `is_test`/test_mode
→ test; `acceptance_test`/is_acceptance → acceptance (NOT `acceptance_test`);
`is_retry`/retry_of → retry; `is_registry_sync`/protocol_type contains
registry_sync|registry_publish/"registry sync" in msg/msg startswith
"registry_publish" → registry_sync; `is_scheduled`/periodic → scheduled_protocol;
then cron, organic_peer, organic_user, unknown. Precedence: calibration/test/
acceptance/retry/registry_sync/scheduled BEFORE cron/organic.

### 4. Analyzer: extract for testability + consumer-side staleness (spec 13/14)
- Producer side already emitted the fingerprint (`input_event_log_sha256`,
  `input_event_count`, `input_min/max_timestamp`, `analyzer_version`,
  `generated_at`) and `--plugin-version/--deployment-id/--exclude-traffic`.
- Extracted the inline main() cohort filtering into pure `cohort_filter(rows,
  filter_version, filter_dep, expected_hash, expected_schema,
  excluded_traffic)` → `(clean, legacy, excluded_by_version,
  excluded_by_traffic, excluded_by_producer)`. Unit-testable without side
  effects (main() writes live files).
- Added consumer-side `validate_report(report, events_path)` → `(ok, reasons)`:
  rejects `report_not_object`, `missing_input_fingerprint/event_count/
  analyzer_version/generated_at/time_range`, `inverted_time_range`,
  `event_log_hash_mismatch` (hash ≠ current events.jsonl bytes), and
  `range_excludes_latest_event` (input_max_timestamp < last line's timestamp).

## Test isolation (important)
Redirect `events.EVENT_LOG` to a temp path in setUp and restore in tearDown.
Do NOT `EVENT_LOG.unlink()` from a test like the old test_phase1b pattern —
that deletes the LIVE `~/.hermes/data/reuse-observer/events.jsonl` (real
harvest data). Pattern:
```python
self._tmp = tempfile.TemporaryDirectory()
self._orig_log = events.EVENT_LOG
events.EVENT_LOG = Path(self._tmp.name) / "events.jsonl"
```
(tearDown: restore + cleanup).

## Counting gotcha
`test_v2418_cases.py` is a STANDALONE script (imports json/sys/os, prints
PASS/FAIL, `3/3 PASS`), NOT a unittest module — `unittest discover` does not
pick it up. Peer totals are `unittest_count + 3` (92 + 3 = 95), which is why
peer141's "75" (72+3) matched my "75" (72+3) while raw discover counts differ
by whether the script is run separately.
