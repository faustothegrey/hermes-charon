## Accepted/fixed

The v2.4.0 findings are addressed:

- versions align at `2.4.2`;
- duplicate nested skill is gone;
- controller-based hook entrypoint is intact;
- plugin and manifest hashes agree;
- composite mutations such as reboot/shutdown/kill/reset/patch/upgrade are rejected;
- unsupported peer targets such as `peer999` are rejected before intervention;
- direct `unsupported_target` dispatch is treated as clean read-only failure;
- conformance reports declare `evidence_scope: local-controller`;
- archive validator requires external or embedded canonical archive hash;
- unit and conformance reports match executed results;
- official status remains conservative: tooling/corpus collection complete; empirical labeling and independent validation pending.

## Main blockers for formal evidence

1. Missing provenance is classified as `organic_live` by raw-event reprocessing.
   - `legacy_unclassified` only applies when aggregating old run files with no `by_provenance`.
   - Required: missing metadata must be `legacy_unclassified`; message-text markers are inferred/unknown, not authoritative.

2. Invalid provenance becomes `organic_live`.
   - Required: invalid explicit stream becomes `unknown` and emits an anomaly.

3. Provenance is process-global instead of request-scoped.
   - Env default is acceptable as startup default, but per-request provenance must flow: hook context → protocol.retrieve() → retriever.retrieve() → emit_retrieval().
   - A gateway can handle concurrent organic and calibration sessions, so env vars must not be the primary per-request mechanism.

4. Human labels are overwritten on analyzer refresh.
   - Current `queue-latest.csv` regenerates `label` and `review_notes` as blank.
   - Required: separate generated candidates from durable labels, e.g. `review/candidates-latest.csv`, `review/human-labels.csv`, `review/queue-merged.csv`, or merge existing labels by stable event_id before rewriting.
   - Durable labels should be append-only and include `review_id`, `event_id`, `label`, `labeler`, `labeled_at`, `notes`, and `dataset_split`.

5. 24h/7d rollups use run generation time, not event time.
   - Historical backlog counted in a recent run appears in 24h windows.
   - Required: event-time buckets or rollups directly from event timestamps.
   - Run time is useful for freshness, not activity-window accounting.

6. Event schema version was not bumped.
   - `SCHEMA_VERSION = "1.0"` remains despite provenance additions.
   - Required: bump additive retrieval-event schema, e.g. `1.1`, to distinguish legacy absent provenance from malformed new events.

7. CSV formula injection is possible.
   - `user_message_preview` and other untrusted strings can begin with `=`, `+`, `-`, `@`, tab, or carriage return.
   - Required: formula-neutralize all untrusted CSV string fields.

8. Active-mode multi-step precision remains too narrow.
   - Known mutation composites are rejected, but unknown second operations still intervene: archive logs, rotate logs, open ticket.
   - Required: supported read operation + sequencing language + any additional uncovered operation → unknown/incompatible → no active intervention.
   - This does not block passive deployment because active remains engineering-lab-only.

## Smaller observations

- Ensure all SKILL.md test-count references say 52 after v2.4.2.
- Archive validator should strongly verify report version, expected total, passed count, and `gate_passed=true`, not only `failed == 0`.
- Local-controller conformance must not be interpreted as pinned CLI/gateway/delegated-agent conformance.
- JSONL collection is thread-safe but not multi-process transactional; acceptable for passive single-process collection, not formal active enforcement.

## Recommended v2.4.3 priorities

1. Make missing provenance `legacy_unclassified` and invalid provenance `unknown`.
2. Pass provenance per request, not through a global environment variable.
3. Preserve human labels across analyzer refreshes.
4. Calculate 24h/7d windows from event timestamps.
5. Bump event schema version.
6. Neutralize CSV formulas.
7. Reject all uncovered multi-step active requests, not only known mutation verbs.
8. Add focused regressions for each item above.

## Operational guidance

Use v2.4.2 dashboard and rollups for:

- collection health;
- rough traffic visibility;
- candidate discovery;
- prioritizing human review.

Do **not** use current provenance counts, review CSV, or 24h/7d windows as formal Phase 0 evidence.
